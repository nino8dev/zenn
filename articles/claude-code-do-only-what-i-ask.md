この記事では、次の動画を踏まえて、Claude Codeに「余計なことをさせない」ための実践パターンを整理します。

- 参照動画: https://www.youtube.com/watch?v=UL8SQ_yHKZc

## 先に結論

Claude Codeを安定させるコツは、次の3点です。

1. スコープを狭く固定する（何をしないかまで書く）
2. 成功条件をテスト可能な形で定義する
3. 手順を段階化し、各段で停止条件を与える

## なぜ「余計なこと」が起きるのか

AIコーディングエージェントは、曖昧な依頼に対して「良かれと思って」補完します。

- 依頼が広すぎる
- 完了条件が曖昧
- 変更範囲が指定されていない

この3つが揃うと、不要なリファクタや別機能の改修が混ざりやすくなります。

## 実務で使う指示テンプレート

そのまま使える短いテンプレートです。

```txt
目的:
- 〇〇を修正する

変更対象:
- 変更してよいファイル: A, B
- 変更禁止: 上記以外

要件:
- 〜を満たすこと
- 〜はしないこと

完了条件:
- テストXが通る
- 差分はY行以内（目安）
- 変更理由を3行で説明

手順:
1. まず調査だけして方針を出す
2. 私のOK後に実装
3. 実装後にテスト結果のみ報告
```

## 追加で効く運用ルール

- 「今は実装しない。調査だけ」のモードを明示する
- 「不明点は質問してから進む」を毎回入れる
- PR/コミット前に「依頼外の変更がないか」自己チェックさせる


## 参考リポジトリ: andrej-karpathy-skills

今回の運用方針をチームに定着させるうえで、次のリポジトリも参考になります。

- https://github.com/forrestchang/andrej-karpathy-skills

このリポジトリは、Andrej Karpathy氏の「LLMコーディングで起きやすい失敗」観点を、
実務向けのガイドラインとして整理したスキル集です。特に次の点が有用です。

- まず前提・仮定を明示してから実装する
- 必要最小限の変更に絞る（過剰実装を防ぐ）
- 変更の成功条件を検証可能な形で定義する

「余計なことをしない」運用を、個人の勘ではなくチームの共通ルールにできるのが強みです。

## まとめ

Claude Codeに「余計なことするな」を教えるのは、
モデル性能の問題というより、指示設計と運用設計の問題です。

- スコープ固定
- 完了条件の明文化
- 段階実行

この3点を徹底すると、出力の安定性はかなり上がります。
